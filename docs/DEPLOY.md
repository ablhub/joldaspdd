# Выпуск релиза и обновление сайта с GitHub

Схема: вы делаете `git push`, при новой метке `v...` GitHub Actions собирает релиз, подписывает его вашим ключом и прикрепляет файл `joldas-release.signed` к релизу GitHub. В админке сайта кнопка «Обновить с GitHub» скачивает последний релиз, сервер проверяет подпись и устанавливает его. Токены GitHub на сервере не нужны.

## Один раз: ключ подписи

1. На своем компьютере (в папке репозитория): `node tools/release_keygen.js ~/joldas-release-key`
   Создаются `release.key` (секретный) и `release.pub` (публичный). Секретный ключ никому не отправляйте и не кладите в репозиторий, сохраните в менеджере паролей.
2. GitHub, репозиторий, Settings, Secrets and variables, Actions, New repository secret: имя `RELEASE_SIGNING_KEY`, значение: весь текст файла `release.key`.
3. На сервере (консоль Servercore или SSH) установите публичный ключ: `sudo joldas-set-release-key < release.pub` (файл `release.pub` сначала перенесите на сервер). До этой команды сервер принимает только релизы, подписанные прежним ключом, а релизы из GitHub с новым ключом отклонит.

## Каждый релиз

1. `git tag v2026.10.01 && git push origin v2026.10.01` (любое имя метки, начинающееся с `v`).
2. На вкладке Actions дождитесь зеленой сборки Release: в разделе Releases появится файл `joldas-release.signed`.
3. Админка сайта, Настройки, «Обновление сайта», кнопка «Обновить с GitHub». Установка занимает около минуты, база и прогресс учеников сохраняются. Статус виден там же.

Если не хотите пользоваться GitHub Actions, можно собрать релиз локально (`node tools/build_release.js release-out`, ключ в `~/.joldas-release-key` или в переменной `RELEASE_KEY_PEM`) и загрузить файл в той же карточке кнопкой «Загрузить и установить».

## Условия и ограничения

- Кнопка «Обновить с GitHub» скачивает релиз без токена, поэтому репозиторий должен быть публичным (в нем код сайта и банк вопросов). Для закрытого репозитория скачайте `joldas-release.signed` со страницы релиза вручную и загрузите его кнопкой «Загрузить и установить».
- Репозиторий по умолчанию `ablhub/joldaspdd`, его можно изменить в поле рядом с кнопкой.
- Сервер скачивает файл только с github.com и устанавливает его только при верной подписи, поэтому подмена файла на GitHub не приводит к установке чужого кода.
- Актуальная сборка проверяется в Actions (workflow CI) при каждом push в main: сборка на трех языках, проверки знаков, SEO, переводов, скорости.
