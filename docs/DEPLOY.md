# Выпуск релиза и автообновление сайта

Схема: вы делаете `git push` в ветку `main`. GitHub Actions прогоняет проверки (workflow CI), и если все зеленое, workflow Release собирает сайт, подписывает его вашим ключом и публикует релиз `v<версия>` с файлом `joldas-release.signed`. Сервер раз в 10 минут смотрит последний релиз репозитория, и если версия новее установленной, скачивает файл, проверяет подпись и устанавливает его. Токены GitHub на сервере не нужны, руками ничего делать не надо.

## Один раз: настройка

1. Репозиторий должен быть публичным (Settings, General, Danger Zone, Change visibility): сервер читает релизы без токена. Секретов в репозитории нет, ключ подписи хранится только в секретах GitHub и у вас.
2. На своем компьютере в папке репозитория: `bash tools/setup_release_key.sh`. Скрипт создает пару ключей в `~/joldas-release-key`, добавляет секрет `RELEASE_SIGNING_KEY` в GitHub (через `gh`, если вы в нем вошли; иначе подскажет, как добавить вручную) и печатает команду для сервера.
3. На сервере (консоль Servercore или SSH) выполните напечатанный блок `sudo joldas-set-release-key <<'KEY' ... KEY`. С этого момента сервер доверяет только релизам, подписанным вашим ключом.
4. Сервер должен уже работать на версии, где есть автообновление (раздел «Автообновление с GitHub» в админке, Настройки). Если его нет, один раз загрузите подписанный файл релиза кнопкой «Загрузить и установить».
5. В админке, Настройки, «Автообновление с GitHub»: переключатель включен по умолчанию, кнопка «Проверить сейчас» показывает, что видит сервер.

## Как выходит обновление

1. Вы пушите изменения в `main`. Правки только в `docs/` и файлах `*.md` релиз не выпускают.
2. На вкладке Actions зеленый CI, затем Release: в разделе Releases появляется `v2026.10.01-1432-abc1234` с файлом `joldas-release.signed`.
3. В течение 10 минут сервер ставит его сам. Статус и время последней проверки видны в админке, Настройки, «Автообновление с GitHub»; установка записывается в журнал действий администратора. Установка занимает около минуты, база и прогресс учеников сохраняются.

Если проверки CI красные, релиз не выпускается и сайт остается на прежней версии.

## Вручную

- Кнопка «Обновить с GitHub» в админке сразу скачивает последний релиз, не дожидаясь очередной проверки.
- Собрать релиз локально: `node tools/build_release.js release-out` (ключ в `~/.joldas-release-key` или в переменной `RELEASE_KEY_PEM`), затем загрузить файл кнопкой «Загрузить и установить».
- Повторно собрать релиз на GitHub без нового коммита: Actions, Release, Run workflow.
- Выключить автообновление: переключатель в админке. Тогда сайт обновляется только кнопками.

## Правила и ограничения

- Новее определяется по дате и времени сборки в версии, поэтому старый релиз сайт назад не откатит. Теги не в формате `v<версия сборки>` сервер пропускает.
- Если версия отправлена на установку, но не встала (ошибка подписи, сбой установки), сервер не повторяет ее бесконечно и ждет следующий релиз. Причину покажет «Обновление сайта» в админке.
- Сервер скачивает файлы только с github.com и устанавливает их только при верной подписи, поэтому подмена файла на GitHub не приводит к установке чужого кода.
- Release падает на шаге «Ключ подписи на месте»: в логе написана причина (пустой секрет, вставлен публичный ключ release.pub вместо release.key, ключ обрезан). Верное значение секрета RELEASE_SIGNING_KEY: содержимое файла `release.key` целиком, от строки BEGIN до END. Лишние пробелы, отступы и сбитые переводы строк сборка исправляет сама. В логе печатается публичный ключ; он должен совпасть с `/opt/joldas-bootstrap/release.pub` на сервере.
- Потерян секретный ключ: создайте новый через `tools/setup_release_key.sh` с другой папкой (`KEYDIR=~/joldas-release-key-2 bash tools/setup_release_key.sh`), обновите секрет GitHub и выполните на сервере новую команду `joldas-set-release-key`.
- Репозиторий по умолчанию `ablhub/joldaspdd`; чтобы сменить его, задайте переменную `GITHUB_REPO` в `/etc/joldas/env` на сервере и перезапустите `joldas-api`.
- Актуальную сборку проверяет CI при каждом push в `main`: три языка, знаки, SEO, переводы, скорость.
